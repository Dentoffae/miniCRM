# EXCEL — мини-CRM, Google Sheets и отчёты

Проект объединяет:

- **Мини-CRM** — REST API на **FastAPI** + **SQLite**, десктоп-клиент на **Tkinter** (`crm/`).
- **Синхронизация CRM → Google Таблицы** через **сервисный аккаунт** (одна таблица, листы клиентов / сделок / задач).
- **Выгрузка отчётов в новую Google Таблицу из GUI** через **OAuth пользователя** (личный аккаунт Google, не сервер).
- Утилиты **Google Sheets API** (`google/`) и отдельное демо-приложение отчётов (`report_app.py`).

**Требования:** Python **3.10+**, Windows в примерах команд (на Linux/macOS замените пути и `python` при необходимости).

## Быстрый старт (мини-CRM)

1. Клонируйте/скопируйте проект, создайте виртуальное окружение и установите зависимости:

   ```powershell
   cd путь\к\EXCEL
   python -m venv venv
   .\venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. Скопируйте `.env.example` в `.env` и при необходимости заполните переменные (см. раздел [Переменные окружения](#переменные-окружения)).

3. Запустите API (по умолчанию `http://127.0.0.1:8000`):

   ```powershell
   python crm\crm.py
   ```

4. В **другом** терминале запустите GUI:

   ```powershell
   python crm\crm_gui.py
   ```

5. В окне GUI укажите URL API (если не подставился автоматически): локально чаще всего `http://127.0.0.1:8000`, при **Docker Compose** — обычно `http://127.0.0.1:8080`.

Альтернатива — **Docker:** из корня проекта `docker compose up --build`; API снаружи слушает порт **8080** (если не переопределён `CRM_PORT` в `.env`). Подробнее: [Запуск через Docker](#запуск-через-docker).

## Мини-CRM: API и данные

### Сущности

- **Клиенты** — имя, контакты, компания, заметки, статус (`active` / `archived`).
- **Сделки** — привязка к клиенту (необязательно), сумма, валюта, статус воронки, номер заказа.
- **Задачи** — привязка к клиенту и/или сделке, срок, признак выполнения.

### Документация API

После запуска сервера откройте интерактивную документацию:

- Swagger UI: `http://127.0.0.1:8000/docs` (или ваш порт / хост).

### Наполнение тестовыми данными

Скрипт в корне проекта создаёт по **N** записей в каждой из трёх сущностей (по умолчанию **1000**):

```powershell
python seed_crm_demo.py
python seed_crm_demo.py --count 500 --base-url http://127.0.0.1:8080
```

Поведение:

- Если `--base-url` **не** указан, скрипт ищет живой ответ на `GET /health`: сначала `CRM_API_BASE_URL`, затем `http://127.0.0.1:8000` и `:8080` (и варианты с `localhost`).
- На Windows консоль переключается на UTF-8, чтобы кириллица в логах не ломала вывод.

Если на сервере включена синхронизация Google после **каждого** `POST`, массовая загрузка будет очень медленной. Для ускорения укажите в `.env` **`CRM_GOOGLE_SYNC=0`** и перезапустите API.

**Важно:** перед запуском скрипта API должен быть запущен (`python crm/crm.py` или Docker). Иначе будет ошибка соединения (например, «connection refused» на порту 8000).

## Десктопный клиент (`crm_gui.py`)

| Элемент | Описание |
|--------|----------|
| Поле **API** | Базовый URL FastAPI (без завершающего `/`). |
| **Проверить** | Запрос к `/health`. |
| **Настройки Google (отчёты)** | Пути к JSON **OAuth-клиента** (тип Desktop, файл `client_secret_….json`), к файлу **token** (создаётся после первого входа; не путайте с `client_secret`), **ID папки** в Google Drive. Настройки сохраняются в `crm/google_report_settings.json`. Рядом с полем папки — кнопка **«Вставить»** (буфер обмена), т.к. в Tkinter бывают проблемы с Ctrl+V. |
| Вкладки **Клиенты / Сделки / Задачи** | Таблицы и формы; кнопка **«Выгрузить отчёт»** строит отчёт в **новой** Google Таблице в выбранной папке (OAuth открывается в **главном** потоке окна). |
| Успешная выгрузка | Окно с **ссылкой** на таблицу и кнопкой **«Открыть в браузере»** (без акцента на сыром ID). |

### OAuth для отчётов (GUI)

1. В Google Cloud Console создайте **OAuth 2.0 Client ID** типа **Desktop** и скачайте JSON (`client_secret_….json`).
2. В первом поле настроек укажите **этот** файл. **Не** используйте JSON **сервисного аккаунта** в поле клиента.
3. Во втором поле укажите путь к будущему **`token.json`** (можно оставить путь по умолчанию в папке `crm/`). После первого экспорта выполните вход в браузере; файл token сохранится.
4. Если менялись области доступа (scopes) у клиента, старый `token.json` может стать недействительным — удалите его и пройдите вход снова.

Папка на Google Drive: откройте папку в браузере и скопируйте **ID** из URL (`folders/ИД_ПАПКИ`).

## Синхронизация CRM → Google Sheets (сервисный аккаунт)

Бэкенд может после изменений данных **перезаливать** содержимое SQLite в **одну** указанную таблицу Google (листы по умолчанию: `CRM_Clients`, `CRM_Deals`, `CRM_Tasks`; имена можно переопределить переменными `CRM_GOOGLE_TAB_*`).

Нужно в `.env`:

- `GOOGLE_SPREADSHEET_ID` — ID таблицы из URL.
- `GOOGLE_APPLICATION_CREDENTIALS` — путь к JSON **сервисного аккаунта**.

Таблицу нужно **расшарить** на email сервисного аккаунта (`client_email` в JSON) с правом не ниже **Редактор**.

Отключить синхронизацию после каждой записи: **`CRM_GOOGLE_SYNC=0`**.

Эндпоинт ручной синхронизации (если реализован в вашей версии API): `POST /sync/google` — смотрите `/docs`.

## Утилита `google_sheets_crud.py`

Клиент `GoogleSheetsClient` для чтения/записи диапазонов, пакетных обновлений, форматирования. Запуск как скрипта печатает содержимое листов (проверка доступа):

```powershell
python google\google_sheets_crud.py
```

Импорт в своём коде:

```python
from google_sheets_crud import GoogleSheetsClient

client = GoogleSheetsClient(
    spreadsheet_id="...",
    credentials_path=r"C:\path\to\service-account.json",
)
```

Основные методы: `get_values`, `update_range`, `clear_range`, `list_sheet_titles`, `sheet_id_by_title`, `spreadsheet_batch_update` и др. (см. исходный файл и старые комментарии в репозитории).

## Переменные окружения

| Переменная | Назначение |
|------------|------------|
| `CRM_API_BASE_URL` | Базовый URL API для GUI и для `seed_crm_demo.py` (приоритет при автоподборе). |
| `CRM_HOST` / `CRM_PORT` | Хост и порт для `python crm/crm.py` (по умолчанию `127.0.0.1` и `8000`). |
| `CRM_DB_PATH` | Путь к файлу SQLite (Docker задаёт `/data/crm.sqlite3`). |
| `GOOGLE_SPREADSHEET_ID` | ID таблицы для синхронизации CRM и для утилит с сервисным аккаунтом. |
| `GOOGLE_APPLICATION_CREDENTIALS` | Путь к JSON сервисного аккаунта. |
| `CRM_GOOGLE_SYNC` | `0` / `false` — не вызывать синхронизацию Google после каждой мутации в API. |
| `CRM_GOOGLE_TAB_CLIENTS` / `…_DEALS` / `…_TASKS` | Имена листов в Google Таблице (если не заданы — значения по умолчанию из кода). |
| `CRM_SEED_COUNT` | Число записей на таблицу для `seed_crm_demo.py` (если не задан `--count`). |

OAuth-пути для низкоуровневых скриптов в `google/` могут задаваться через `GOOGLE_OAUTH_CLIENT_SECRETS` и `GOOGLE_OAUTH_TOKEN_PATH` (см. `.env.example`).

## Устранение неполадок

| Симптом | Что проверить |
|---------|----------------|
| GUI не видит API | Запущен ли `crm.py` или Docker; совпадает ли порт (8000 vs 8080); firewall. |
| `seed_crm_demo.py`: connection refused | API не запущен; либо укажите `--base-url` на фактический хост/порт. |
| Отчёт Google: неверные JSON / «авторизуйтесь» | В первом поле — **client_secret** Desktop, во втором — **token.json**, не наоборот; не подставляйте ключ сервисного аккаунта вместо OAuth-клиента. |
| `403` / нет доступа к таблице (сервисный аккаунт) | Таблица расшарена на `client_email` из JSON ключа с ролью **Редактор**. |
| Синхронизация CRM тормозит массовую загрузку | `CRM_GOOGLE_SYNC=0` на время `seed_crm_demo.py`. |
| Ошибки `tkinter` | Установите Python с компонентом Tcl/Tk или системный пакет `python3-tk` (Linux). |
